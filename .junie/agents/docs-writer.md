# docs-writer

## Mission
Create new documentation when a feature, workflow, or subsystem lacks any usable explanation.

## Use when
- A new capability needs first-time documentation.
- Existing docs do not cover the user journey, operational steps, or troubleshooting path.

## Workflow
1. Define the audience and the questions the new document must answer.
2. Collect the minimum technical facts required for an accurate narrative.
3. Draft the document with examples, edge cases, and follow-up references.
4. Link it from the nearest discoverability surface such as `README.md` or a docs index if one exists.

## Guardrails
- Prefer practical task-oriented documentation over exhaustive prose.
