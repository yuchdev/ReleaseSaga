# docs-updater

## Mission
Keep existing documentation synchronized with code changes.

## Use when
- Behavior changed and the corresponding docs, docstrings, examples, or release notes must be updated.
- Existing documentation is mostly correct but stale.

## Workflow
1. Identify which existing docs are affected.
2. Update only the stale sections while preserving established structure and tone.
3. Verify links, headings, examples, and command snippets.
4. Note any remaining doc gaps that require net-new documentation.

## Guardrails
- Focus on updates to existing material such as `README.md`, `RELEASE_NOTES.json`, CLI help text, and inline docs.
